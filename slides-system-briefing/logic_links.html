核心邏輯一：連結是業務邊界

這套系統不是只用公司或建案去模糊判斷住戶入口，而是把 booking link 當成真正的公開入口與管理邊界，避免不同建案、驗別與時段池互相混用。
CORE DEFINITION
一筆公開連結， 就是一條被明確控制的預約入口。
它不只是給住戶點擊的網址，而是把公開流程、可用時段、驗別規則與停用狀態綁在一起的業務邏輯單位。
如果沒有這條邊界，系統表面上只是入口變多；實際上會變成 資料混池、責任模糊、客服負擔上升。
規則
業務意義
每一筆公開預約都綁定正式連結
住戶不是從模糊首頁進站，而是從特定入口進入特定流程，避免不同建案彼此干擾。
時段屬於單一連結
同一組時段不會被多個公開入口共用，時段容量與開放範圍因此有明確邊界。
驗別可跟著連結切分
初驗、複驗或不同活動批次可以拆成獨立入口，不必靠人工提醒住戶自己分辨。
連結可被啟用、停用與限期
公司能決定何時開放、何時關閉，以及住戶在錯誤時點看到什麼訊息，而不是被動收件。
這種設計的本質，是把「對外公開網址」升級成可被治理的營運資產，而不是一次性行銷連結。
如果沒有 link 邊界
住戶可能從同一首頁進入不同建案；行政得靠人工辨識該走哪個驗別；時段看似共用，其實會讓 錯建案、錯時段、錯入口 同時發生。
導入後的實際效益
公司可以把每一次對外開放視為一筆正式入口：誰能進、能約哪個建案、可用哪些時段、何時停用，都有清楚的控制點，也更容易在後台追查問題來源。
