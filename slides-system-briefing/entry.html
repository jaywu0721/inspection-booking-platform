角色入口已被重新定義

目前系統採用 同一主網域、不同參數分流角色 的策略。沒有預約參數時，根網址直接作為管理入口；帶有正式分享參數時，才會進入住戶預約流程。
PATH A｜無分享參數
根網址直接進管理員登入
內部人員不需要再手動輸入 /admin。從實際使用角度看，入口變短，教育成本也更低。
SINGLE DOMAIN ENTRY
inspect.eaglebuilt.company
用同一個主網址承接兩種角色，但用參數與路徑條件把管理端與住戶端流程分開。
PATH B｜帶正式 link 參數
分享連結仍保留住戶預約流程
住戶只從專屬連結進入，不再把首頁當公開入口，能降低誤入錯建案或錯驗別的機率。

這個策略的優點是入口清楚、品牌網址更短；風險是 分享參數一旦遺失或被手動改動，住戶就無法進入正確的預約頁面。因此正式營運上，連結傳遞與客服話術必須一起配套。
